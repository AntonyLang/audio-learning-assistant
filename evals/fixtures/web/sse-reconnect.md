# SSE 断线重连与事件序号

## 为什么不能使用全局自增

Server Sent Events 的 Last-Event-ID 是一个按连接游标。如果事件序号来自一张全局自增表，事务 A 先取到序号 10、事务 B 取到 11 但先提交，客户端在 11 之后断线，重连时按 last id 回放就会永远错过 10。

按 run 维度加行锁递增序号，并把事件与业务状态放在同一个事务里提交，才能保证"序号大的事件一定后提交"。这是可恢复流的前提，而不是性能优化。

## 回放与快照

客户端带 Last-Event-ID 重连时，先回放该游标之后的事件，再继续轮询同一份持久日志。如果游标已经超出保留期，服务端应返回状态快照与一个新的游标，并且两者来自同一个一致性读。

心跳只是为了避免中间代理断开空闲连接，不承载业务语义。页面关闭不应该取消后台任务，取消需要单独的接口。
