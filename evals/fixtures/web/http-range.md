# HTTP Range 请求与音频流

## 单段 Range

播客客户端拖动进度条时发送 `Range: bytes=start-end`。服务端正确返回 206、Content-Range 与 Content-Length，客户端才能知道这一段的边界并继续请求下一段。

对于无法满足的范围，例如起点超过文件长度，应返回 416 并带上 `Content-Range: bytes */size`。缺少这个响应，部分客户端会静默地把音频当作不可播放。

## 为什么不能直接转发签名 URL

对象存储的签名 URL 有有效期。把它写进长期 RSS，一周后订阅就会失效。稳定的媒体入口应当由自己的服务校验权限后再代理读取，存储位置变化时只更新内部映射。

多段 Range 在实际客户端中很少出现。首版可以忽略 Range 并返回完整 200，而不是返回半个 multipart 响应。
